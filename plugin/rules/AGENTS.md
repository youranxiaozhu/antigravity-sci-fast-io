# Sci Fast IO — 科研极速工作规则 v2.0

目标：最小化任务端到端耗时、无效工具回合与上下文膨胀；严守科研数据真实性与修改可验证性。

## 1. 任务分级与收尾

- **简单常规任务**（单文件修复、超参数调整、局部代码/文献检索、数据表探查、单张论文图微调）：直接定位、执行并验证，**不主动新增计划文档、Todo 清单或长篇总结文件**。
- **复杂长程任务**（跨多模块架构重构、从零设计实验方案、多阶段管线搭建，或用户明确要求规划）：使用规范的规划与分步验证流程。
- **及时收尾**：证据足以回答问题或验证通过后立即收尾，不做无关的扩展翻阅。

## 2. 检索与读取策略

- **已知文件**：直接用 `read_file` 读取目标范围；300 行以内的源码/配置/文稿整份读，大文件带 `StartLine` / `EndLine` 一次读足 150–200 行，相距 200 行以内的多处合并为一段读；读过且未改动的文件不重读。
- **未知位置**：先用一条检索命令拿到命中文件与行号，**下一轮将所有确定要看的文件一次性并行 `read_file`**，拒绝“读一个、想一轮、再读下一个”。
- **递归 `grep` 安全规范**：使用 `grep -Rn -I` 时必须显式指定源码/文稿子目录（如 `'src'` `'scripts'` `'paper'`）或加 `--include='*.py'` / `--exclude-dir='.venv'`；禁止对工作区根目录 `.` 或 `.venv`、`wandb`、`lightning_logs` 执行无过滤递归扫描。注意 `git ls-files` 不包含尚未 `git add` 的新建实验脚本。

## 3. 科研数据与 Notebook 保护（配合 PreToolUse 硬门禁）

- **二进制与压缩科研文件**（`.parquet` `.feather` `.npz` `.npy` `.pt` `.ckpt` `.safetensors` `.h5` `.h5ad` `.rds` `.bam` `.nii.gz` `.fastq.gz` `.vcf.gz` 及目录型 `.zarr`）：严禁直接文本读取；按需读取 `sci-eda` 技能，用单次 Python/R 脚本一次性探查 `shape`、`dtype`、缺失率与摘要统计。
- **科研文本数据**（`.csv` `.tsv` `.vcf` `.fasta` `.pdb` `.cif` 等）：`<= 32 KiB` 小汇总表可直接读取；`32 KiB ~ 2 MiB` 仅限 `<= 80` 行有界读取或用免审命令 `ls -lh`、`wc -l`、`head -n 5` 看表头；`>= 2 MiB` 一律走抽样或脚本探查。
- **Jupyter Notebook（`.ipynb`）**：按字节体积而非行数判断风险。`> 32 KiB` 的 Notebook 禁止直接全文读取（防单行巨型 base64 图像撑爆上下文）；`< 5 MiB` 可用 `jq` 提取 `source` 并排除 `outputs`，更大文件用单次 Python 脚本按 cell 索引提取（参考 `sci-eda`）。
- 被 `PreToolUse` 门禁拒绝时，立即改用其提示的有界命令或脚本，不重复提交等价的大范围读取请求。

## 4. 命令执行：桌面端免审直通 vs 计算编译合并

- **简单只读查看默认走桌面端免审白名单**（省去每次 2–5 秒云端审查排队）：
  `ls` `cat` `head` `tail` `wc` `grep` `diff` `stat` `du` `jq` `which` `pwd` `echo` `basename` `dirname` `realpath`，以及长参数格式只读 `git`（`status` / `diff` / `log --max-count=N` / `show` / `ls-files` / `rev-parse`），允许单管道 `|` 串联。
  - 写免审命令时：只写裸命令名，不写 `cd`、`&&`、`||`、`;`、`>`、`2>/dev/null`、`$(...)`、反引号及前置变量 `VAR=val`；glob/正则与含空格路径一律加引号。
  - **效率逃生阀**：若遇上万文件的深层松散目录、免审 `grep` 的无效 I/O 耗时明显高于一次 3 秒审查成本时，允许改用带过滤的 `rg` / `fd` 以最小化总耗时。
- **必审命令合并执行**：`python3`、`uv`、`Rscript`、`pytest`、`xelatex`、`pdflatex`、`latexmk` 等本来就要送审的命令，将互不依赖的步骤（如“EDA 多指标统计”或“跑绘图脚本/LaTeX 编译 + 产物校验”）合在**单次脚本或单条 `&&` 命令**里一次跑完，步骤间用 `echo '== STEP =='` 分隔并截断冗长宏包日志（如 `| tail -n 30`）；依赖前一步结果才能决策的操作仍分步执行。

## 5. 编辑与三步批量验证

- 局部修改优先用 `edit_file`，同一文件相邻几处合并为一次 `edit_file`，跨文件互不依赖的修改同轮并行发出；`grep` 整行已能唯一定位时可直接调 `edit_file`。
- **跨多文件批量替换三步闭环**（尤其涉及论文引用键 `\cite{}`、数据路径、实验配置字段）：① 先核对匹配位置与总数量 -> ② 执行最小范围替换 -> ③ 跑免审 `git diff` 复核并运行最小必要验证。

## 6. 主上下文瘦身与 `research` 子代理分流

- 不向主对话倾倒完整数组、大段原始表格或上千行检索回显。
- 面对陌生大型代码库、跨模块复杂调用链或预计需多轮翻阅大量文件的广度调研，当子代理冷启动开销小于主会话多轮长推理耗时时，优先委派只读 `research` 子代理在隔离上下文完成探索，并要求其返回 **`文件路径 + 行号 + 关键证据结论 + 未核实事项`**。

## 7. 科研真实性与交付规范

- **科研真实性红线**：严禁编造、估算或硬编码实验数值、`p` 值、误差棒、置信区间、文献 DOI/PMID 或数据库编号；严格区分实测结果、推断与假设；未运行验证的操作不得声称已完成。
- **进度与篇幅**：遵循全局汇报规则，在发起并行工具调用的**同一轮回复中**用 1–2 句话同步实质进展（不单独拆空转回合）；日常调试问答结论与指标先行、控制在 1,500 字以内，撰写论文正文、同行评审与规范统计报告时按学术标准完整展开。
